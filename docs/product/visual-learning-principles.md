# Visual Learning Principles

## Product Position

Industrial Learn is a visual-first, simulation-first engineering learning platform. Students should encounter a physical or system phenomenon before detailed exposition, then connect observation to theory, calculation, diagnosis, and application.

Visual-first does not mean evidence-light. Every technical claim, equation, state transition, fault signature, instrument reading, and real-world assertion remains subject to the existing source and engineering-review controls.

## Primary Learning Sequence

`SEE -> INTERACT -> OBSERVE -> EXPLAIN -> CALCULATE -> CONNECT -> BREAK -> DIAGNOSE -> APPLY`

| Step      | Student action                                     | Platform responsibility                                      |
| --------- | -------------------------------------------------- | ------------------------------------------------------------ |
| See       | Notice an engineering phenomenon                   | Present a clear initial state and learning purpose           |
| Interact  | Change a meaningful variable or component          | Provide bounded, accessible controls with immediate feedback |
| Observe   | Describe the consequence                           | Ask prediction and observation questions before explanation  |
| Explain   | Build the governing concept                        | Offer concise labels, callouts, and micro theory             |
| Calculate | Relate the state to a reviewed equation            | Use `engineering-core` and explicit SI units                 |
| Connect   | Link physical, internal, and schematic views       | Keep component identity and state synchronized               |
| Break     | Introduce an evidence-supported fault              | Change domain state, not decorative appearance               |
| Diagnose  | Select measurements and justify a conclusion       | Use state-derived virtual instruments and controlled hints   |
| Apply     | Transfer the concept to a challenge or real system | Use reviewed scenarios and licensed or original visuals      |

Not every lesson requires all nine actions. Definitions, safety briefings, and orientation lessons may use a reduced pattern, but suitable engineering phenomena should not begin with several paragraphs.

## Experience Weighting

For suitable lessons, target approximately:

- 60-70% simulation, animation, visualisation, and interaction.
- 15-20% concise explanation.
- 10-15% calculation.
- 5-10% assessment and reference.

These are pedagogical weights, not pixel quotas or mandatory time-on-page ratios. Learning outcomes and evidence determine the final balance.

## Depth Modes

### Quick

The default for a first visit: visual state, plain-language explanation, essential labels, and an observation prompt.

### Engineering

The reviewed equation, SI units, symbol definitions, assumptions, limitations, and a worked example.

### Deep Dive

Derivation where appropriate, edge cases, advanced explanation, source details, and links to prerequisite knowledge. Deep Dive preserves academic depth without blocking exploration.

The selected mode changes explanation density, not the underlying engineering state or answer policy.

## Non-Negotiable Learning Rules

1. One domain state drives every representation, instrument, equation display, and accessible summary.
2. Engineering formulas remain pure tested functions outside UI components.
3. Animation cannot manufacture values or hide invalid calculation results.
4. A student must be able to operate every essential interaction by keyboard and by a non-drag control.
5. Colour reinforces meaning but never carries it alone.
6. Motion communicates engineering change; decorative motion is excluded from learning surfaces.
7. Opening a lesson, moving a control, or spending time does not by itself award progress or competence.
8. Hidden assessment answers remain unavailable before submission.
9. Faults are enabled only when their behaviours and diagnostic signatures have approved evidence or an explicitly reviewed educational model.
10. Visual claims use the same source and review governance as written claims.
11. Every heavy experience has a low-data fallback and must not block the readable lesson shell.
12. Mobile layouts recompose controls and measurements instead of shrinking a desktop canvas.

## Visual Authenticity

The platform may simplify a system to teach one governing relationship, but simplifications must be labelled. Scale exaggeration, omitted losses, idealised geometry, shortened time, or illustrative motion must appear in assumptions or limitations. Manufacturer ratings, standard clauses, property data, and fault thresholds are never inferred from appearance.

## Progress And Competence

Visual activity becomes evidence of learning only when tied to an outcome-bearing action, such as a correct observation, a validated calculation, successful operation, an evidence-based diagnosis, or an assessed design decision. Explore mode may be recorded as practice without automatic mastery.

## Content Governance

Visual blocks inherit the lesson version, source references, and review status. Equations and simulations retain their own review records. A published lesson that embeds an unapproved visual model may show only a clearly labelled non-technical fallback; it cannot imply that the model is reviewed.

## Design Language

Industrial Learn should feel like a clear engineering workbench: white and orange brand surfaces, disciplined typography, restrained panels, explicit instrument readings, real component geometry where useful, and consistent state symbols. The experience may be vivid without using futuristic decoration, ornamental 3D, or motion unrelated to the engineering lesson.
