# Visual Lesson Release Checklist

Version: 1.0.0

Record evidence beside every item. A checked box is not a substitute for the required
review record.

## Learning Architecture

- [ ] The declared `lessonType` matches the primary learning outcome.
- [ ] The lesson follows a category-appropriate order rather than a copied template.
- [ ] The title, purpose, main visual, and primary control/start action are visible in the
      first representative desktop and mobile viewport.
- [ ] Interaction appears before detailed theory.
- [ ] Outcomes and prerequisites remain available in compact form.
- [ ] Observation precedes explanation where prediction is part of the outcome.
- [ ] Micro Theory contains one concept without repeated hero or Deep Dive prose.
- [ ] Deep Dive is optional and preserves required academic detail.

## Engineering Integrity

- [ ] Engineering-core drives all calculated values.
- [ ] Internal calculation units are consistent SI units.
- [ ] Display conversions are explicit and unit formatting is consistent.
- [ ] Every input declares quantity, units, bounds, step, validation, model validity,
      accessibility label, and educational purpose.
- [ ] Every output declares quantity, units, interpretation, validity, warning policy, and
      measurement source.
- [ ] Visual scale, motion, and geometry do not overclaim model fidelity.
- [ ] Unsupported dynamics, ratings, faults, or properties are absent.
- [ ] Normal, boundary, invalid, and supported fault states have automated tests.

## Interaction And Challenge

- [ ] Each control changes a meaningful state or view.
- [ ] Slider controls have numeric alternatives.
- [ ] The challenge defines goal, allowed actions, success condition, feedback, and model
      assumptions.
- [ ] Practice feedback appears after an intentional Check action.
- [ ] Graded scoring and answer protection remain server controlled.
- [ ] Success wording does not imply professional design or safety approval.

## Visual And Responsive Quality

- [ ] The main visual is legible at desktop, tablet, 430 px, 375 px, and 320 px widths.
- [ ] Mobile content recomposes and has no horizontal overflow.
- [ ] Vector magnitude is bounded and its visual normalization is disclosed.
- [ ] Normal, active, selected, warning, fault, disabled, measurement, and target states use
      shared semantics and non-colour cues.
- [ ] The real-world application is concise, relevant, source-linked, and bounded.
- [ ] The route loads only the required visual experience and respects the route budget.

## Accessibility

- [ ] All controls operate by keyboard in a logical order.
- [ ] Current state and checked challenge feedback are announced concisely.
- [ ] Gauges, vectors, cutaways, schematics, and applications have text alternatives.
- [ ] Meaning never relies on colour alone.
- [ ] Reduced-motion behaviour removes unnecessary transitions without removing meaning.
- [ ] Browser zoom and mobile text resizing remain usable.
- [ ] Automated accessibility checks and a manual keyboard pass are recorded.

## Governance

- [ ] Every important technical statement has an approved or honestly review-gated source
      ID.
- [ ] Equation, simulation, safety, content, and publication review statuses are accurate.
- [ ] Published content has a named independent reviewer and versioned review record.
- [ ] No author self-approval occurred outside an explicit policy exception.
- [ ] Source records are available without dominating the primary learning path.
- [ ] The audit report lists tests, performance evidence, known limitations, and remaining
      review work.
